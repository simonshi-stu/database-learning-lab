# 订单服务进阶项目：分支验收
- 学习路径：基础练习、PostgreSQL 实战、云后端选修、C++ 内核选修分开。订单项目从基础课链接进入，六个文件逐步组成一个服务。
- 前置能力检查：基础课已有主/外键、条件扣减、事务回滚、并发等待和幂等重试；HTTP 请求合同、健康检查、部署和故障取证由新项目逐步引入。各章可从项目回到相应基础题。
- 聚焦回归：SQLite 起始解判错/参考解通过；无 PostgreSQL 驱动的干净环境能启动，相关课程显示跳过；DuckDB 在合成输入上实写实读 Parquet，验证全量、正确单日、单日误查全量、错误日期、零汇总。
- 项目用例：参考文件经 CPython 和 Pyodide 0.27.7 各验证 16 个方法；错误起始 SQL 在 Pyodide 失败。后续章节依赖的是上次通过的前置文件。
- [真实 Kubernetes 验收](https://github.com/simonshi-stu/database-learning-lab/actions/runs/45043679608)：临时 kind 集群，前后 Pod UID 不同，Service 就绪端点都随 Pod 更新；两个健康检查端点均为 200，挂载卷声明 UID 未变。首次下单库存 5→4，同键重放仍为 4，新订单再变为 3。实验清理步骤通过。
- 边界：真实结果来自参考文件在单节点教学集群的验证，只证明应用 Pod 换代和数据保留，不代表跨节点高可用或零停机。浏览器内测试不会创建集群；下载学生版本后，用自己的 GitHub Actions 运行真实实验。本轮没有重跑 63 关，也未端到端复测私有站点中登录后的 UI 和基础题历史界面。
